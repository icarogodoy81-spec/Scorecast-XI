Key Routes (src/app/api/)
api/fixtures/route.ts
GET — reads fixtures FROM Supabase (not from football API) for frontend display.
Uses service role client.
Optional filter param: league_id (NOT competition/league_name — those don't exist as columns).
Selects: id, home_team_name, away_team_name, home_team_logo, away_team_logo, fixture_date, status_short, round, home_goals, away_goals, league_id
Maps to { matches: [...] } shape consumed by frontend (home_team, away_team, utcDate, status, group_name, score.fullTime.home/away).
Called from: src/app/boloes/page.tsx and src/app/predictions/page.tsx (no query params currently sent).
api/[something]/route.ts (the league/season sync route — separate from above)
GET — pulls fixtures FROM API-Football LIVE, then upserts INTO Supabase fixtures table.
Required query params: league (league id), season.
Calls https://v3.football.api-sports.io/fixtures with header x-apisports-key.
Maps API response → row shape matching fixtures table columns (id, league_id, season, round, home_team_id/name/logo, away_team_id/name/logo, date, status, home_score, away_score, updated_at).
Upserts with onConflict: 'id'.
NOTE: need to confirm exact file path/folder name for this route (wasn't fully given — need to re-locate, likely something like api/sync-fixtures/route.ts or similar).
api/predictions/route.ts
GET — requires logged-in user (supabase.auth.getUser()), returns user's predictions from predictions table: match_id, home_score, away_score filtered by user_id.
POST — upserts a prediction: body { matchId | fixtureId, homeScore, awayScore }. Upsert key: user_id,match_id on table predictions. Requires logged-in user.
