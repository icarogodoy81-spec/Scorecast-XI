1. Expanded Achievement Badges System
To make badges meaningful, they need to be tied to specific user behaviors and milestones.

Badge Categories:

Accuracy Badges: "Sniper" (5 exact scores in a week), "Perfect Weekend" (100% correct outcomes in a specific league round).
Behavioral Badges: "Early Bird" (submitted all predictions 48h before kickoff), "Buzzer Beater" (submitted a prediction less than 5 minutes before kickoff).
Loyalty Badges: "Centurion" (100 predictions made), "Die-Hard" (played 30 consecutive days).
Rarity Badges: "The Oracle" (predicted a 0-0 draw that actually happened).
Supabase Implementation Logic: Instead of calculating badges on the fly, use a Supabase Edge Function triggered by a database webhook on the predictions or match_results update.

sql


-- Enhanced Badge Schema
CREATE TABLE badges (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  name TEXT UNIQUE NOT NULL,
  description TEXT NOT NULL,
  tier TEXT CHECK (tier IN ('bronze', 'silver', 'gold', 'platinum')),
  condition_type TEXT NOT NULL, -- e.g., 'exact_scores_total', 'streak_length'
  condition_value INT NOT NULL,
  icon_url TEXT
);

CREATE TABLE user_badges (
  user_id UUID REFERENCES profiles(id) ON DELETE CASCADE,
  badge_id UUID REFERENCES badges(id) ON DELETE CASCADE,
  unlocked_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  is_new BOOLEAN DEFAULT TRUE, -- Used to trigger frontend celebration animations
  PRIMARY KEY (user_id, badge_id)
);
2. Private Mini-Leagues (User Acquisition & Retention)
Global leaderboards get stale for users who join late. Allowing users to create private leagues with invite codes drives organic growth as they invite friends/coworkers.

Architecture:

sql


CREATE TABLE private_leagues (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  owner_id UUID REFERENCES profiles(id),
  name TEXT NOT NULL,
  invite_code TEXT UNIQUE DEFAULT substring(md5(random()::text) from 1 for 8),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

CREATE TABLE private_league_members (
  league_id UUID REFERENCES private_leagues(id) ON DELETE CASCADE,
  user_id UUID REFERENCES profiles(id) ON DELETE CASCADE,
  joined_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  PRIMARY KEY (league_id, user_id)
);

-- View to calculate private league standings dynamically
CREATE OR REPLACE VIEW private_league_standings AS
SELECT 
  plm.league_id,
  p.id AS user_id,
  p.username,
  p.total_points, -- Or calculate points specifically for the timeframe of the league
  RANK() OVER (PARTITION BY plm.league_id ORDER BY p.total_points DESC) as rank
FROM private_league_members plm
JOIN profiles p ON plm.user_id = p.id;
3. Tactical Boosters (Multipliers)
Give users a limited number of "Boosts" per game week (similar to Fantasy Premier League's "Triple Captain"). This adds a layer of strategy beyond just guessing the score.

The "Joker" / "Banker": The user selects one match per week where they are highly confident. Points earned for this match are doubled.
Implementation:
sql


-- Alter predictions table to include booster flags
ALTER TABLE predictions
ADD COLUMN is_joker BOOLEAN DEFAULT FALSE;

-- Create a function to validate only 1 joker per user per game week
CREATE OR REPLACE FUNCTION check_joker_limit() 
RETURNS TRIGGER AS $$
BEGIN
  IF NEW.is_joker = TRUE THEN
    IF (
      SELECT COUNT(*) 
      FROM predictions p
      JOIN matches m ON p.match_id = m.id
      WHERE p.user_id = NEW.user_id 
      AND p.is_joker = TRUE 
      AND m.gameweek = (SELECT gameweek FROM matches WHERE id = NEW.match_id)
    ) > 0 THEN
      RAISE EXCEPTION 'Only one Joker allowed per gameweek';
    END IF;
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER enforce_joker_limit
BEFORE INSERT OR UPDATE ON predictions
FOR EACH ROW EXECUTE FUNCTION check_joker_limit();
